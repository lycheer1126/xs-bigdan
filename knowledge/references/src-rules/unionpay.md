# USRC（银联安全应急响应中心）平台规则

> 来源：USRC 漏洞处理流程及评级标准（2026-01 版）。**目标命中银联资产时本文件优先**。
> 提交入口：security.unionpay.com（注册需关联绑定云闪付账号）· 金币≈1 元，需云闪付绑卡兑换。
> 邮箱：usrc@unionpay.com · 申诉：结果一周内，内部仲裁委员会裁定。

## 1. 评级锚点（五级：严重/高危/中危/低危/忽略）

**【严重】**：集中生产云服务器权限（任意代码执行/命令执行/Webshell/SQLi 拿核心系统权限）、
**大量持卡人个人信息**（用户ID/姓名/手机号/设备信息/财产信息/证件号码/证件照/银行卡号/生物识别/
密码类鉴权信息）、核心应用业务数据批量泄露。

**【高危】**：
- 逻辑设计缺陷：任意账号登录、任意密码修改、关键环节短信/邮件验证码绕过
- 持卡人个人信息**批量泄露**（SQLi/越权/未授权）
- 一般应用业务数据批量泄露
- 其他信息泄露：任意文件包含/读取、源代码泄露、客户端加密算法可破解
- **SSRF：能直接访问内网且可获取回显（需证明，且不得对内网服务扫描）** ⭐
- 资金损失：任意金额支付、任意账号支付

**【中危】**：
- 需交互获取用户身份信息（可获得管理员权限的存储 XSS、重要敏感操作 CSRF）
- 越权：普通用户批量越权查看他人信息、管理后台访问
- 管理员弱口令、客户端提权到 root/管理员、远程窃取客户端数据
- 绕过限制获取优惠（大量重复享受受限优惠）
- **SSRF：能直接访问内网但无回显** ⭐

**【低危】**：无数据的 SQLi / Jsonp、非敏感操作 CSRF / 一般信息泄露（路径/SVN/LOG/Phpinfo/页面遍历）/
一般越权改删他人信息 / 无限制短信邮件、图形验证码绕过 / 反射 XSS / **URL 跳转** / 本地 DoS /
撞库爆破遍历（非敏感数据）/ 内部员工弱口令 / 应用缺陷远程 DoS。

**【忽略】**：不能复现 / Self-XSS / **IP 地址/域名泄露** / 无意义源码泄露 / 用户名枚举 / SPF 邮件伪造 /
无意义 API Key 泄露 / 静态目录遍历 / 非银联授权范围（第三方嵌入应用、外包测试系统）。

## 2. 计数与时效（硬规则）

- 同一漏洞只认**首个提交并证明真实存在**的报告者
- **同一应用系统同一类型漏洞只收前 3 个**，后续不予认领
- 通用漏洞（Struts2/Java 反序列化类）**披露第 1 周内**仅认定首个有效 PoC 且证明银联应用受影响；
  1 周后仍未修复的按单洞处理

## 3. 红线（违规 = 终止全部权利 + 追责）

- **高频扫描**：通过银联安全监控系统对比发现高频扫描行为 → 直接终止 USRC 全部权利；
  造成损失的依法追偿 → ⚠️ 对 Agent 的含义：**串行限速纪律在此平台必须最严**（SAFE MODE 全程，QPS 压到最低）
- 测试到 **POC 证明可利用为止**，严禁拖库、内网渗透等非法操作
- 社工获取的权限必须证明信息可直接利用并有后续风险，否则按低危/中危第 8 条处理
- 禁止在任何公共渠道/自媒体公开漏洞细节

## 4. 对 Agent 的操作映射

- **SSRF 分级明确**（全平台最清晰）：有回显=高危、无回显=中危——hunt_ssrf 的 store-and-read
  盲打变回显手法在此平台**直接把中危升成高危**，优先做。
- 报告写法：证明"访问了内网 + 拿到什么"两段都要有；**严禁对内网服务扫描**（与我们只证明可达即停一致）。
- 限速：全程 SAFE MODE 最严档；`--timeout`/间隔拉长，宁可跑不完不触发风控。
- 同类型 3 个上限：与 compliance"越权 ≤5 条"取更严者（此平台 ≤3）。
