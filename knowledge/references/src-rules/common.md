# 跨平台公约（五家 SRC 规则的共性提炼——对所有目标生效）

> 来源：AntSRC / 58 / USRC(银联) / DXMSRC / 小红书(部分) 评分标准交叉比对。
> 用途：目标未命中特定平台文件、或需要快速判断"这个发现值不值得报"时的通用判据。
> 目标命中特定平台 → 以 `src-rules/<平台>.md` 的平台特化规则为准（本文件与特化冲突时，特化优先）。

## 一、评级共性（五家通用的定级骨架）

全部为五级制（严重/高危/中危/低危/忽略）× 应用/业务系数。判断锚点的行业共识：

| 级别 | 行业共识锚点 |
|---|---|
| 严重/高危 | 服务器权限、webshell、大量敏感数据（身份/资金/交易）、核心逻辑（支付/账密）、可命令执行的 SQLi、无需交互的存储 XSS、**有回显可入内网的 SSRF** |
| 中危 | 需交互才危害用户（反射XSS/敏感操作CSRF）、普通信息泄露（登录后的手机号/姓名）、越权查看、无回显 SSRF、营销作弊 |
| 低危 | 特殊条件才可利用、路径/phpinfo、无限制短信邮件（部分平台）、URL 跳转、无敏感数据的越权 |
| 忽略/无影响 | Self-XSS、恶作剧 CSRF、IP/内部域名泄露、静态目录遍历、用户名枚举、无法证明的猜测、产品体验问题 |

## 二、普遍不收/低价值清单（提交前逐条自查）

- Self-XSS（无法影响他人）；恶作剧 CSRF；无法影响他人的本地 DoS
- IP 地址/内网域名泄露（仅证明可达不算——需数据或凭证）
- 账户/手机号枚举；≥8 位密码与认证信息爆破；邮箱轰炸（58 明确不收；短信横向轰炸 DXM 不收）
- HTTPS 明文传输（无 MITM 实证）；静态文件目录遍历；SPF 邮件伪造；无意义 API Key
- 产品体验/设计问题；运营预期内的小额奖励活动（多账号领小额=正常）
- 无任何证据的猜测；"能加固"≠漏洞（无攻击场景的防御建议）

## 三、计数与提交共性

- **同源合并**：同一漏洞源多洞计一（银联：后续按 75%；DXM：打包提交 1.1 倍——同源策略方向相反，按平台文件执行）
- **同类型上限**：AntSRC/银联=同域名同类型最多确认 3 个 → Agent 产出同类发现时**测深 3 个**即停
- **首发原则**：同一漏洞只认首个提交者；通用漏洞披露第 1 周仅认首个有效 PoC
- **报告拆分**：多数平台"同一报告多洞按最高计"→ 高价值发现单独成报告

## 四、测试纪律共性（违规 = 0 分/终止权利/报案）

- **测试到 POC 证明可利用为止**：严禁拖库、内网渗透、webshell、权限维持（银联/DXM 明文 0 分+报案）
- **高频扫描 = 终止全部权利**（银联明文）——串行限速纪律在此类平台必须最严
- **保密**：未脱敏细节外发/未修复公开 → 收回奖励甚至封号（所有平台一致）
- 禁止以测试为名损害用户利益、影响业务、盗取数据

## 五、时效共性

- 通用漏洞（nday）披露第 1 周内首发有效；已知晓的 nday 驳回；超期未修按实际演示定级（需 CVE+PoC）
- 部分平台 3 年外事件不受理（AntSRC）

## 六、各平台特色差异（速记）

| 平台 | 特色 |
|---|---|
| AntSRC | 金币=基础×应用系数（核心应用×10）；同域名同类型≤3；内网IP泄露=无影响；1day 时效规则 |
| 58 | 权重公式自动计算；`*.58.com` ≠ 58 资产（外包合作最高中危）；回显SSRF=8 分 vs 无回显=3 分 |
| 银联 | SSRF 分级最清晰（回显=高危/无回显=中危）；高频扫描终止权利；金币需云闪付绑卡兑换 |
| DXMSRC | 1 积分=5 元；同源打包 1.1 倍；内网越界 0 分+报案；独立威胁情报赛道（完整度五维系数） |
