# 58SRC（58同城）平台规则

> 来源：58SRC 漏洞评分标准官方页。**目标命中 58 资产时本文件优先于通用评级标准**。
> 提交入口：security.58.com · 金币:RMB = 1:10 · 争议先查 FAQ 再评论区，仲裁依《58SRC 审核争议解决办法》。

## 1. 业务分级（Scoping 红线——域名 ≠ 业务）

- **核心**：58同城（招聘/房产/本地服务/大学）、58同镇、赶集网、安居客
- **一般**：转转、找靓机、58金融、58心宠、58车、驾校一点通、中华英才网
- **其他**：58魔方、英才企业站等真 58 资产
- **外包合作**（最高只算中危，无直接影响不收录）：爱房、58天鹅到家、伯小乐——**即使存在命令执行**。
  ⚠️ 业务不按域名划分：`*.58.com` 域名可能跑的是驾校一点通业务（外包）——按漏洞影响的实际业务定，域名仅供参考。
- 特例：XSS 若能读取 `58.com` 域 Cookie → 按核心业务算。

## 2. 评分公式（自动计算，等级只与漏洞价值有关）

```
漏洞价值 = 漏洞权重 × ((影响强度+影响范围)² × 0.024 + (影响强度+影响范围) × 利用难度 × 0.048) + 漏洞权重 × 0.6
```

## 3. 漏洞权重分级（定级锚点）

**【8-10】服务器影响/越权/逻辑**：远程命令执行(10)、代码执行(10)、脚本上传 getshell(10)、
任意账号登录(9)、任意密码重置(9)、直接刷钱的支付漏洞(9)、核心DB大量敏感数据 SQLi(8)、
服务端加密数据可逆(8)、**回显型 SSRF(8)**。

**【6-7】严重信息泄露/设计缺陷**：越权增删改核心功能与数据(7)、严重信息泄露(7)、业务逻辑拒绝服务(7)、
XSS+CSRF 蠕虫(7)、客户端任意代码执行(7)、造成营收损失的漏洞(6)、XXE(6)、授权密钥硬编码(6)。

**【3-5】需交互/普通逻辑/普通信息泄露**：打客服/管理员的存储XSS(5)、越权增删改非核心(5)、非核心数据
泄露(5)、**无限制短信轰炸(4, 需 5 分钟 50 条证明)**、邮件伪造(4)、敏感操作 CSRF/Jsonp 敏感/CORS 敏感(3)、
客户端明文存密(3)、其他轰炸缺陷(3)、**无回显 SSRF(3)**。

**【1-2】轻微**：轻微敏感信息泄露(2)、**无交互任意 URL 跳转(2)**、HTTP 明文传输(1)。

## 4. 明确不收清单（Agent 判定防坑——命中即不报）

静态文件目录遍历 / CRLF 注入 / 除 DOM 外的反射 XSS / Self-XSS / 无敏感操作的 CSRF（收藏点赞购物车）/
需扫码二次交互的 URL 跳转 / 账户手机号枚举 / ≥8 位密码与认证信息爆破 / 邮箱轰炸 / HTTPS 明文传输 /
正常业务活动小额奖励（多账号领奖=运营预期内）。

**注意与 hunts 冲突点**：邮箱轰炸在 58 = 不收（其他平台多为低危）——以目标所属平台规则为准。

## 5. 计数与惩罚

- **同源漏洞 = 源漏洞奖励的 75%**，无等级、不参与活动（含"已修复被绕过"=同源）。
- 漏洞传播（含白帽之间交流 58 业务漏洞）扣 20 金币，情节严重封号。
- 员工/外包/渠道禁提交；非对外公开系统不收录。
- 测试仅限证明性测试，严禁破坏性测试与权限维持；敏感操作（删/改）无意造成危害应及时报告。

## 6. 对 Agent 的操作映射

- Scoping：`*.58.com` 不自动等于 58 资产——按 JS/业务特征判定真实业务归属，外包业务直接跳过。
- 高价值靶点：回显 SSRF(8) 值得优先打；无回显 SSRF 只有 3 分——**有回显价值是无回显的 2.7 倍**，
  store-and-read 盲打变回显（hunt_ssrf §6）在此平台收益放大。
- 短信轰炸类：58 要 5 分钟 50 条证明——与我们"≤3 次验证"纪律冲突的部分**不做**，仅记录接口特征写疑似点。
