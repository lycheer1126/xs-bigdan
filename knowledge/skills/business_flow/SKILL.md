# 登录态功能点遍历（business_flow）

> 模型知道 IDOR 概念，但不知道"`status` 要试 `-1`、`id` 要试加 `.5`"这种实战肌肉记忆。
> 本 skill 就是肌肉记忆的成文化。**触发条件：BRIEF 注入了测试账号/Cookie，进入 linkage/deep 阶段。**

---

## 0. 何时读（识别信号）

- BRIEF 有「测试 Cookie」或「测试账号」段 → 认证后攻击面打开，本 skill 为主打法
- recon 产出 `_endpoint_params.json` 且存在需登录的业务端点
- 目标是 OA/CRM/电商/工作流/AI 对话等重业务应用

---

## 1. 四问框架（每接触一个功能点，依次问一遍）

| # | 问题 | 攻击动作 | 工具/字典 |
|---|------|---------|----------|
| 1 | **服务端信这个值吗？** | 参数扰动：状态翻转/类型替换/数量放大/置空 | `references/biz-mutations.md` |
| 2 | **限制在前端还是后端？** | 返回包改写/并发/请求变体（换 cookie、加参数、编码变体） | 竞态→`race_condition/SKILL.md` |
| 3 | **这个对象能换成别人家的吗？** | 水平越权：替换 id/手机号/邮箱/unionid/企业id；返回包 id 回注 | 值池联动引擎 + §3 |
| 4 | **这段内容会再渲染吗？** | XSS 落点探测（冷门载体优先） | §5 落点清单 |

> 四问的顺序即优先级：越权(问3)出洞率最高，先换对象再扰动参数，最后看渲染。

## 2. 寻路（先找面，再打点）

1. **隐藏路由**：`/test` `/m` `/admin` `/dev`；删除/替换路径段再访问；SPA 路由表穷举
   （`vue-spa-attacks.md`）；待审核/未激活状态直接访问目标路由，看是否只挡了入口不挡路由。
2. **半登录态爆破**：带 Cookie 跑 `xsenum`/`ffuf` 打认证后 API 面（401=存在 vs 404=不存在
   差分）；低权限账号能枚举出的接口，就是高权限功能的探测面。
3. **Cookie 创建机制**：分析 set-cookie 链——是否仅凭手机号即可创建会话？携带他人 session
   值即可生效？登录态有无绑定 UA/IP？（发现"会话=弱凭据"即接管链入口）
4. **同子域模式迁移**：同厂商/同栈的洞会成串出现。指纹命中后 grep 台账与 `cve-chains.md`
   同栈案例，把已验证的打法平移过来。
5. **路由切换差分**：清空 history → 切换页面路由 → 看增量加载了哪些接口（抓包对比）。
   跳 SSO 的页面也要跑一遍。
6. **返回包是地图**：响应中出现的 id/索引/链接，**一定手工放回请求包试**（当前引擎值池
   来自 JS 静态分析，不覆盖实时响应——这是人工/agent 判断区）；修改返回包让前端渲染
   "已授权"状态 → 观察它新调用的接口 → 这些就是隐藏面。

## 3. 功能点遍历操作序列（每个功能点走一遍）

```
枚举操作(按钮/表单/导出/分享/审核/归档…) → 逐操作抓包 → 四问框架
→ 命中即测(扰动/替换/并发) → 落证据 → 下一个功能点
```

- 枚举来源：页面 DOM、前端路由表、JS 里的功能开关、菜单树
- 每个操作至少记录：请求参数全集 + 响应字段全集（响应字段是下一轮的输入）
- **高危信号立即深挖**：响应中出现新 id / 请求参数带对象归属（userId/orgId/fileId）/
  功能名带"导出/批量/管理/审核"

## 5. XSS 冷门落点清单（问4的落点，先看这些再找输入框）

| 载体 | 场景 | 备注 |
|---|---|---|
| 文件名 | 上传/下载/列表展示文件名 | 存储型，常被漏过滤 |
| 邀请码/兑换码 | 注册/激活流程回显 | html 注入 |
| @ 解析 | 邮箱/IM/@提及触发特殊解析 | 内容可控即注入 |
| X-Forwarded-For 回显 | 返回"hello, IP"类页面 | 头注入 |
| 登录框记住我 | 前台保存登录信息并回显 | `admin"onmouseover="alert(1)` |
| 二维码/分享链接 url | 生成分享 → 修改 url 参数 | 兼做开放重定向 |
| pdf/图片预览 | 预览页渲染原始内容 | pdf-xss + content-type: text/html |
| AI 对话回显 | 种子/消息内容在列表/详情渲染 | 配合 `ai_chat_xss/SKILL.md` 升级链 |

## 6. 认证与找回流程（与 `xs_auth/SKILL.md` 协同）

- 验证码强度：`codeLength` 改 4 位后爆破；`sms_code=true` 参数直通；验证码步骤"包分离"
  （登录请求直接发，验证步骤替换返回 200）
- 退出接口带手机号参数 → 替换为他人手机号 = 越权踢下线
- 修改密码需原手机验证 → 拦截改返回包为"正确流程" / 找免验证的同功能路由
- 邮箱/短信链接里的参数（邮箱/手机号/token）→ 替换
- 登录态判定：改 cookie 中 base64 可解码的鉴权值 = 任意用户

## 7. 钱与权益状态机

- 类型翻转：支付 `type` 1↔3/40、`userfrom` 直通会员、低价服务 id 替换高价下单
- 先囤后付：多次生成低价订单 → 支付阶段替换；再次购买复写商品 id 重复吃新人礼
- 免费通道进付费内容：免费课程接口加入付费课程；过期活动带 id 复活
- 并发族：并发开发票、购买+提现同发、限额类（私信 5 条/签到）并发绕过 →
  `race_condition/SKILL.md`（业务场景触发段）

## 8. 合规边界（TIER，动手前对照）

> 行为红线（会话/写操作/类型取舍）的唯一权威：`references/src-discipline.md`——本节只列量化阈值，冲突处以纪律文件为准。

- 越权证明 ≤5 条真实记录；两账号差分优先（自己的 A/B 账号互打是金标准）
- 短信/邮箱轰炸：≤3 次变体验证存在性即停，禁止持续
- 支付测试：0.01 级测试单 + 自己的账号，验证后取消/退款
- 并发：≤50 路、≥3 轮、只打测试账号（`race_condition` 强制规则）

## 9. 输出要求

- 每个命中：证据文件（请求/响应原文）+ `FINDING: 类型|标题|文件|状态` 行
- 类型映射：问3→越权/IDOR；问2→认证绕过/竞态；问4→存储型XSS；§7→业务逻辑
- 遵守 triage 四项机械检查（类型/URL/证据/影响），不满足自动降 PENDING
