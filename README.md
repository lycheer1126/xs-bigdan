# xs-bigdan

**Agent 自动化 SRC 漏洞挖掘系统：薄 Harness + Pi Agent + 知识飞轮**

这是一个面向授权 SRC 场景的自动化渗透测试流水线。它把一次黑盒测试拆成五个阶段交给大模型 Agent 执行，而自己只做模型做不可靠的事：控制进度、验证产出、约束边界、沉淀经验。使用者提供授权目标和测试凭据，系统自动完成测试并产出带证据链的报告，人的角色只剩授权、供给与复核。

> 操作规范见 [docs/USAGE.md](docs/USAGE.md)，架构详解见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)，VPS 夜跑部署见 [docs/DEPLOY.md](docs/DEPLOY.md)，演进路线见 [docs/BACKLOG.md](docs/BACKLOG.md)。
>
> ⚠️ 仅限明确授权的目标（SRC 收录 / 书面委托）。未授权渗透测试违法，因使用本项目产生的后果由使用者自行承担。

## 为什么写它

把大模型直接放进真实 SRC 环境干活，很快会撞上三件事。

第一，模型的陈述不可信。它会声称完成了实际没做完的侦察，会把猜想写成"已确认"，会在上下文变长之后判断力明显下滑。渗透测试恰恰是一个"进度和结论都必须可信"的学科——向 SRC 提交一个误报，损失的是账号信誉。

第二，模型的输出不受物理规律约束。它不会主动限速，遇到 WAF 可能硬闯，预算烧完之前不知道停。真实目标背后是企业的生产环境和法务边界，一次失控的自动化足以酿成事故。

第三，模型的知识有截止日期，而且不含私有经验。它听说过泛微 E-cology 的通识，但不知道你上个月在某站点实测出的接口缺陷；它懂 IDOR 的原理，但不掌握你在几十个真实目标上磨出来的那种"这个参数要试 -1、那个 id 要加小数点"的手感。

传统扫描器解决了第二件事，代价是把测试逻辑焊死在代码里，面对陌生技术栈就僵化；纯 Agent 方案解决了第一件事，代价是没有纪律。xs-bigdan 试图同时要两样：**把纪律交给代码，把判断交给模型。**

## 核心思路

这个系统里只有一条最高决策：模型的说辞不作为任何状态的依据，文件系统才是唯一的信任锚点。由此往下推，整座建筑的结构就定了。

**进度等于产物，不等于模型的自述。** 调度器判断任务处于哪个阶段，依据是磁盘上有没有通过检查的产物文件：recon 阶段产出的接口契约要完整度达标、端点数量达标，linkage 阶段才被允许开始；指纹与 WAF 状态确认之后，高危探测才被允许开始。模型说"我做完了"没有意义，文件在、内容对，才算数。这条规则同时完成了两件事——进度可信，以及合规次序（先侦察后深打）被物理性地固定下来。

**但文件系统信任锚点有一个前提：上下文必须保鲜。** 大模型的能力随上下文膨胀而衰减，一场九十分钟不间断的会话，后半段的模型又笨又贵。于是每个阶段都由一个全新的会话执行——上一段的模型和这一段的模型素不相识。失忆是切片的代价，补偿手段是三通道记忆：上一段留下的结构化交接文档负责叙事，运行日志里的事件流负责事实，Agent 自己落盘的会话文件负责容灾——即使输出管道出了故障，调度器也能从会话文件把交接内容找回来。这不是理论设计，每一条通道都对应过一次真实事故。

**新会话对世界的全部认知来自那份任务简报。** 所以简报的装配质量就是 Agent 的质量上限：本阶段该读哪些知识文件、值池联动引擎生成的测试配对、测试账号、登录态 Cookie、乃至创建任务时写下的一句"我觉得这里薄弱"。装配做得越准，模型发挥越好——这是整个系统里人力投入回报最高的地方。

**模型会放弃，也会幻觉，所以要有刹车和质检。** Agent 遇到阻力说"打不动了"时，调度器能识别出这是放弃信号，强制注入换角度重试的指令；任务真正卡住时，Agent 可以主动声明 BLOCKED 求助，调度器停下整个任务等人补给线索，而不是让它硬耗预算。到了报告环节，每条"已确认"的发现都要过一道机械核验——有类型、有 URL、有证据文件、有影响描述，缺任何一项自动降级。误报不出厂，是编码进系统的价值观。

**最后，经验必须能沉淀，否则系统只是个昂贵的一次性工具。** 知识层全部是 Markdown 文件：操作手册、速查表、决策树，以及最重要的实战台账。每份真实报告消化后回流知识层，下个目标自动生效。这些经验分两种粒度——案例级的（某类厂商系统的具体打法，指纹命中后整段平移）和动作级的（对任意参数都成立的扰动原子，比如"状态值要试负一""分页参数要试一万"）。前者是私有经验的护城河，后者是手感的编码。知识的加载是按需的，每个阶段只注入命中的两三个文件，这也是上下文保鲜在知识层的延伸。

把上面的推导压缩成一条因果链，就是系统的骨架：

```
模型的说辞不可信
  └→ 进度 = 落盘产物（阶段状态机，Safe-First 次序被物理固定）
上下文增长导致劣化
  └→ 每段全新会话（切片）
       └→ 切片必然失忆
            └→ 交接文档 + 事件流 + 会话日志（三通道记忆）
模型的全部认知来自简报
  └→ 简报装配 = 质量上限（知识索引 / 联动配对 / 凭据 / 意图 注入）
模型会放弃、会幻觉
  └→ 停止信号三通道 + 投降检测 + triage 机械核验
模型的知识有截止日期、不含私有经验
  └→ 知识外挂 + 实战飞轮（案例级台账 + 动作级扰动字典）
```

## 一次任务的生命周期

```
🟢 recon      指纹与 WAF 被动识别、JS 全量落盘、接口契约提取
     │ 门: 契约完整度 ≥0.8 且端点 ≥3
     ▼
🟡 linkage    全接口覆盖、值池联动（A 接口响应值自动注入 B 接口）、无认证探测
     │        （有凭据时进入认证后攻击面：越权 / IDOR / 业务逻辑）
🟡 deep       JWT 分析、前端加密破解、端点榨干（无 JWT 且无加密体则跳过）
     │ 门: 已确认 ≥1 个漏洞
     ▼
🔴 highrisk   高危探测（SQLi / 命令注入 / SSTI / 越权），全程限速
     ▼
📋 report     证据汇总 → triage 机械核验 → 报告归档
```

登录态场景下，Agent 按"功能点遍历"方法论工作：对每个功能点依次追问四个问题——服务端真的信任这个值吗、这个限制在前端还是后端、这个对象能换成别人的吗、这段内容会再次渲染吗。这些问题连同对应的扰动字典，全部来自真实测试经验的消化。

执行层故意做得很薄：不构造多角色子 Agent，不封装 MCP 工具集，模型通过 bash 组合一套命令行工具完成测试。工具只负责把原始输出翻译成 AI 友好的差异表、并把每次请求的原文自动落盘为证据。Agent 的手是 bash，工具就该是 CLI——跨平台零适配，换一个 Agent 循环（比如 pi 换成别的）也依然成立。

## 知识飞轮

知识层分三层。`agents/` 是阶段角色卡，告诉模型"这个阶段你是谁、交付什么"；`skills/` 是操作手册，一类攻击的完整步骤，特征命中才加载；`references/` 是速查表，WAF 签名、决策树、扰动字典、CVE 利用链，查完即走。另有 `experience/` 实战台账记录案例级经验，属私有资产不入库。

飞轮的转动方式：实战产出的报告和日志，经人工消化后写成新的手册条目或台账案例，在方法论读取表中登记触发条件，下个目标自动生效。全程零代码改动——知识层的载体是文件，改文件就是改行为。

## 工程组成

```
bigdan.py            调度器：目标解析 → 阶段判定 → 简报装配 → 分段执行 → 收尾报告
core/                agent 会话执行器 / 值池联动引擎 / 投降检测 / 报告与 triage 硬门
prompts/             常驻提示词（铁律纪律 + 阶段门控方法论）
knowledge/           知识层：agents 角色卡 ×7 · skills 手册 ×22 · references 速查 ×27 · 实战台账
webui/               控制台：串行任务队列 / 配置 / 历史报告 / Cookie 与用户意图注入
tools/               命令行工具：请求、枚举、无头浏览器、字典体系
runtime/             运行产物（自动生成，不入库）
```

## 快速开始

依赖 Python 3.10+、Node.js 22+ 与 [pi-coding-agent](https://github.com/badlogic/pi-mono)，以及任一 OpenAI 兼容的大模型 API Key。

```bash
pip install -r requirements.txt
copy .env.example .env                    # 填写模型 API Key
copy targets.example.txt targets.txt      # 每行一个授权目标
python bigdan.py --dry-run && python bigdan.py
```

日常推荐使用控制台：

```bash
python -X utf8 -m webui.server            # http://127.0.0.1:8865
```

支持整批粘贴目标、按站点隔离的多账号 Cookie 注入、任务中途补给线索。VPS 夜跑形态（systemd 托管、串行队列、睡前入队早上收报告）见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 安全边界

本系统仅用于获得明确授权的目标。测试范围被白名单物理约束在 `targets.txt` 之内；越权验证以不超过五条数据为证明尺度；禁止 DoS、批量爆破与破坏性操作，登录尝试限速且命中即停；密钥、凭据与在测目标不入库。使用者须自行确保对目标拥有合法授权，因使用本项目产生的后果由使用者承担。
