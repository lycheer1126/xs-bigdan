# xs-bigdan

**Agent 自动化 SRC 漏洞挖掘系统** —— 薄 Harness × 通用 Agent × 外挂知识层

面向授权 SRC 场景的自动化渗透测试流水线：确定性调度器负责装配、门控与收尾，大模型 Agent 依据阶段方法论完成黑盒测试，产出带完整证据链的 Markdown 报告。人的职责被压缩到三项——**提供授权、提供凭据、复核报告**。

>
> ⚠️ **仅限明确授权的目标**（SRC 收录 / 书面委托）。未授权渗透测试违法，因使用本项目产生的后果由使用者自行承担。

## 一、问题定义

将大模型应用于真实 SRC 渗透测试，存在三重矛盾：

1. **能力与可靠性错配** —— LLM 具备渗透知识，但会自报虚假进度、产生幻觉、上下文增长后判断力衰减、遭遇阻力时提前放弃；
2. **学科纪律刚性与模型自由度冲突** —— 渗透测试要求"侦察不充分不深打、误报毁信誉、越界即违法"，无法依赖模型自觉；
3. **传统方案的僵化** —— 扫描器把测试逻辑写死在代码里，面对陌生技术栈即失效；纯 Agent 方案又没有纪律与止损。

**xs-bigdan 的回答**：把纪律从模型手中拿走交给代码，把判断从代码中拿出来交给模型。由此推导出整个系统。

## 二、设计公理

系统的核心判断是：**LLM 本身就是能力，Harness 只配承担确定性的工作——装配、门控、收尾。**

1. **薄 Harness**：调度器不写死任何测试逻辑，仅负责五件事——阶段状态机（以落盘产物门控）、上下文切片（每段全新会话防止模型劣化）、停止信号（求助 / 建议结束 / 预算尽三通道）、装配（向任务简报注入角色卡、知识索引、凭据与用户意图）、收尾（triage 机械核验 + 报告）。测试思路全部存在于 `knowledge/` 与 `prompts/` 的 Markdown 中，**修改文件即修改行为**。
2. **通用 Agent 循环**：执行层采用 [pi-coding-agent](https://github.com/badlogic/pi-mono)，不构造多角色 Subagent，不封装 MCP 工具集；模型自行组合命令行工具完成测试。Harness 的唯一立场是合规与止损，而非教授模型如何渗透。
3. **知识外挂与实战飞轮**：知识按需加载（每段仅读命中的 2-3 个文件，防止上下文泛滥）；实战报告持续消化回流知识层，Agent 随使用增强。
4. **双通道记忆**：段间状态由"交接文档（叙事）+ 会话日志（事实兜底）"双通道传递，输出捕获失败也不会丢失交接——调度器绝不因停止信号丢失而空烧预算。
5. **合规内建**：Safe-First 门控次序、操作分级（TIER）、报告核验硬门、登录限速红线均在 Harness 层强制，不依赖模型自觉。

## 三、设计的因果链

各机制并非并列的功能清单，而是逐条推导的结果：

```
公理「信任锚点是文件系统，不是模型的陈述」
  └─→ 进度 = 落盘产物，而非模型自报
        = 阶段状态机：recon 契约完整度 ≥0.8 才许进入联动，
          指纹/WAF 确认后才许高危探测（Safe-First 次序）
公理「上下文增长导致模型劣化」
  └─→ 每段 = 全新会话（上下文保鲜切片）
        └─→ 切片必然失忆 → 需要段间记忆
              = 交接文档（叙事）+ 事件流（事实）+ 会话日志（容灾兜底）
                ——三通道，缺任何一条都有真实事故对应
公理「模型对世界的全部认知来自任务简报」
  └─→ 简报装配质量 = Agent 质量上限
        = BRIEF 注入：阶段知识索引 / 值池配对 / 账号 / Cookie / 用户意图
公理「模型会放弃、会卡死、会幻觉」
  └─→ 停止信号三通道（结构性止损）+ 投降检测（强制换角度）+ triage 机械核验（误报不出厂）
公理「模型的知识有截止日期，且不含私有经验」
  └─→ 知识外挂 + 实战飞轮：案例级台账（同栈打法平移）+ 动作级字典（任意目标通用的扰动原子）
```

## 四、创新点

| # | 设计 | 传统做法 | 差异 |
|---|------|---------|------|
| 1 | **进度 = 落盘产物** | 定时/轮次驱动，或信任 Agent 自报 | 阶段推进以可验证的产物文件为门，卡住即停在原地等人 |
| 2 | **上下文保鲜切片 + 双通道记忆** | 单会话连续执行 | 每段全新上下文保持判断力；叙事+事实+容灾三通道保证交接不丢 |
| 3 | **停止信号三通道** | 无止损或硬超时 | Agent 主动求助（BLOCKED）、自评完成（建议结束）、预算约束三通道，结构性杜绝空烧 |
| 4 | **知识飞轮双层消化** | 静态知识库 | 实战报告消化为案例级台账与动作级扰动字典，私有经验成为持续增长的护城河 |
| 5 | **工具 CLI 化** | MCP / 函数调用封装 | Agent 的手是 bash，工具即命令行脚本：AI 友好输出、自动落盘证据、双平台零适配 |
| 6 | **triage 机械硬门** | 信任 Agent 的 CONFIRMED | 类型/URL/证据/影响四项核验，不过自动降级——误报不出厂 |
| 7 | **合规内建** | 合规作为提示词建议 | 白名单、操作分级、Safe-First 次序、限速红线均在 Harness 层强制 |

## 五、系统如何工作

一次任务分五个阶段顺序推进，进入下一阶段的条件是**产出物落盘并通过检查**，而非时间流逝：

```
🟢 recon      指纹 + WAF 被动识别 + JS 全量落盘 + 接口契约
     │ 门: 契约完整度 ≥0.8 且端点 ≥3
     ▼
🟡 linkage    全接口覆盖 + 值池联动（A 接口响应值自动注入 B 接口）+ 无认证探测
     │        （注入凭据时，进入认证后攻击面：越权 / IDOR / 业务逻辑）
🟡 deep       JWT 分析 / 前端加密破解 / 端点榨干（无 JWT 且无加密体则跳过）
     │ 门: 已确认 ≥1 个漏洞
     ▼
🔴 highrisk   高危探测（SQLi / 命令注入 / SSTI / 越权），全程限速
     ▼
📋 report     证据汇总 → triage 机械核验 → 报告
```

每个阶段由**全新上下文**的 Agent 执行，段间依靠双通道记忆衔接——因此任务可以长时间无人值守运行、中断可续、状态不丢。登录态场景下，系统执行**功能点遍历方法论**（四问框架：服务端是否信任该值 / 限制在前端还是后端 / 对象能否替换 / 内容是否再次渲染），并以两账号差分作为越权验证的金标准。

## 六、系统组成

```
bigdan.py            调度器：目标解析 → 阶段判定 → 简报装配 → 分段执行 → 收尾报告
core/
  agent_exec.py        Agent 会话执行器（限流重试 / 超时强杀 / 双通道日志 / 失败归档）
  linkage.py           值池联动引擎（接口契约 × 泄露值池 → 测试矩阵）
  retry_detector.py    投降检测（Agent 过早放弃时注入换角度指令）
  report.py            报告生成 + triage 机械核验硬门
prompts/             常驻提示词：铁律纪律 + 阶段门控方法论
knowledge/           知识层（全 Markdown）
  agents/              阶段角色卡 ×7
  skills/              操作手册 ×22（业务遍历 / 登录审计 / JS 分析 / AI 应用攻击 …）
  references/          速查 ×27（决策树 / WAF 签名 / 扰动字典 / CVE 链 / 合规 TIER …）
  experience/          实战台账（案例级经验，gitignore）
webui/               控制台（串行任务队列 / 配置 / 历史报告 / Cookie 与用户意图注入）
tools/               命令行工具（请求 / 枚举 / 无头浏览器 / 字典体系）
runtime/             运行产物（自动生成，不入库）
```

## 七、快速开始

**依赖**：Python 3.10+、Node.js 22+ 与 [pi-coding-agent](https://github.com/badlogic/pi-mono)、任一 OpenAI 兼容的大模型 API Key。

```bash
pip install -r requirements.txt
copy .env.example .env                    # 填写模型 API Key
copy targets.example.txt targets.txt      # 每行一个授权目标
python bigdan.py --dry-run && python bigdan.py
```

控制台方式（推荐）：

```bash
python -X utf8 -m webui.server            # http://127.0.0.1:8865
```

支持整批粘贴目标、按站点隔离的多账号 Cookie 注入、任务中途补给线索。VPS 夜跑形态（systemd 托管 + 串行队列 + 睡前入队早上收报告）见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 八、安全边界

- 仅测试 `targets.txt` 白名单内的授权目标；禁止 DoS、批量爆破与破坏性操作
- 内置操作分级：越权验证 ≤5 条数据作为证明、危险工具不默认启用、登录尝试限速且命中即停
- 敏感文件（密钥、凭据、在测目标）均不入库，模板见 `.example` 文件
- 使用者须确保对目标拥有合法授权
