# xs-bigdan

**Agent 自动化 SRC 漏洞挖掘系统：薄 Harness + Pi Agent + 知识飞轮**

> 操作规范见 [docs/USAGE.md](docs/USAGE.md) · 架构详解见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) · VPS 夜跑部署见 [docs/DEPLOY.md](docs/DEPLOY.md) · 演进路线见 [docs/BACKLOG.md](docs/BACKLOG.md)

## 一、本质：一句话与一个比喻

**xs-bigdan = 把资深渗透工程师的工作纪律编码成确定性代码（harness），让 LLM 在严格围栏内做它擅长的事（判断与联想）。**

理解它的最好比喻是一个侦探社：

| 比喻 | 系统组件 | 职责 |
|---|---|---|
| 项目经理（不懂技术，只懂流程纪律） | `bigdan.py` 调度器 | 分配案子、控制预算、验收交付物、决定下一步 |
| 外聘侦探（每次案子都请一个新的） | pi agent + LLM | 真正去现场勘查的人 |
| 案卷移交单 | BRIEF.md | 新侦探上任时读的第一份文件 |
| 团队知识库 | `knowledge/` | 侦探按需翻阅的手册和过往案例 |
| 工具房 | `tools/` | 勘查器材 |
| 前台 + 案件看板 | webui | 与使用者交互的地方 |
| 结案报告审核人 | triage 硬门 | 不相信侦探的一面之词，机械核验 |

这个比喻里藏着全部核心设计决策。下面沿一个目标的一生走一遍，每个环节展开。

## 二、一个目标的一生（主流程，10 步）

### 第 1 步：在 webui 创建任务

粘贴 `URL|备注`，可选填 Cookie（多账号框）和「我的想法」。这一步发生四件事：

1. URL 写入 `targets.txt`——这就是白名单，合规的第一道墙（Agent 只测这个清单里的 host）
2. 生成任务 ID，建 `runtime/jobs/<id>/` 目录——Cookie 和想法**不进** `targets.txt`（那是要进 git 的），而是写成任务目录里的 `cookies.txt` 和 `intent.md`（gitignored 区）
3. 任务进入队列——串行绝不并行，靠 `pid_alive()` 判断有没有活进程
4. 队列 tick 拉起 `bigdan.py` 子进程——注意是孤儿进程（脱离 webui 进程树），关电脑、重启 webui 都杀不死它

### 第 2 步：调度器接手，写 BRIEF（全系统最核心的装配环节）

调度器调 `write_brief()` 生成 BRIEF.md——给侦探的案卷移交单。它按固定结构装配：

```text
目标 ID / URL / 备注
白名单（合规边界）
阶段判定 + 依据              ← infer_phase() 算出来的
入口聚焦（如果 URL 带路径）    ← 使用者"先打这个薄弱点"的意图
读取索引（本阶段建议读哪些知识文件）← 知识飞轮的阀门
联动配对（如果值池有货）       ← 联动引擎的输出
用户线索（中途喂的）/ 用户意图（建任务时写的）
测试账号（账号池匹配的）/ 测试 Cookie（cookies.txt 过滤后的）
工具清单（绝对路径）+ 字典分级
```

**关键理解：BRIEF 是模型与系统之间唯一的"合同"。** 模型每段全新上下文，它对这个世界的一切认知都来自这份文件，所以简报的质量直接决定 Agent 的质量——入口聚焦、Cookie 段、意图段，每一个都是在给模型喂"它不可能自己知道的信息"。

### 第 3 步：阶段判定——相位状态机（为什么"进度=产物"）

`infer_phase()` 判断当前该处于哪个阶段。它不看时间、不听模型自报，只看磁盘上的产物：

| 门 | 证据（落盘文件） |
|---|---|
| recon → linkage | `_endpoint_params.json` 存在 + JS 分析完整度 ≥0.8 + 端点 ≥3 |
| linkage 开工 | `_fingerprint.md` 存在（WAF 状态已确认） |
| linkage 有产出 | `_linkage_results.jsonl` ≥1 条 |
| → deep | 无 JWT 且无加密体 → 跳过 |
| → highrisk | 已有 ≥1 CONFIRMED；有 WAF 则全程 SAFE MODE |
| → report | 攻击面收尽 或 digest 标注「建议结束」 |

为什么这么设计：LLM 会自报"我做完了"（实际没做完）、会谎报进度。唯一可信的是文件在不在磁盘上、内容过不过检查——**信任锚点是文件系统，不是模型的嘴**。

这也解释了 Safe-First：🟢recon（纯侦察）→ 🟡linkage/deep（普通测试）→ 🔴highrisk（高危探测）的次序不是装饰，是合规要求的编码——没摸清 WAF 和指纹之前不许打高危。

### 第 4 步：spawn pi——执行层

`run_pi_session()` 启动 pi 进程，三个后台线程保驾护航：

- **tee 线程**：pi 的 stdout → session 日志（GBK 编码事故就出在这条管道上）
- **jsonl 镜像线程**：实时读 pi 自己落盘的会话文件 → 也写进日志（容灾兜底通道靠它）
- **心跳线程**：每 10s 写一行 `timeout_left=xxxx`——实时日志里看它倒数就知道活着

主线程只干一件事：`proc.wait(timeout=段预算)`。预算到点 → 杀进程 → 下一阶段。这就是为什么任务永远不会无限跑。

### 第 5 步：Agent 干活（模型的世界）

拿到全新上下文的模型，行为路径被设计得非常窄：

1. 读 BRIEF.md（唯一的任务来源）
2. 按读取索引 grep 命中的 2-3 个知识文件（不许多读，防上下文泛滥）
3. 用工具房的家伙干活：xsreq 发请求落证据、xsenum/ffuf 枚举、browser_probe 驱动浏览器、按字典分级爆目录
4. 确认的洞 → `evidence/` 写证据文件 + 打 `FINDING: 类型|标题|文件|状态` 行
5. 收工前输出 `### RECON_DIGEST`（交接文档）或 `### BLOCKED`（求助）

这就是"工具 CLI 化"的答案：Agent 的手只有 bash，所以每个能力必须封装成命令行可调用、输出 AI 友好、自动落盘证据的脚本。xsreq 发一个请求就存一份请求+响应原文（证据链的原子单位）；xsenum 自动取 404 基线再把异常项排前面（把 ffuf 的原始输出翻译成 AI 一眼能读懂的差异表）；browser_probe 把浏览器动作封装成 open/js/chunks/login/snow 五个子命令。MCP 不用、函数调用不用——**bash + stdin/stdout 就是最通用的 Agent 接口**，且跨 Windows/Linux 零适配。

### 第 6 步：段结束——三通道决策

pi 退出后，调度器按顺序检查：

```text
1. 提取 FINDING 行 → 合并进 summary（跨段去重；stdout 丢了从 jsonl 兜底恢复）
2. 提取 RECON_DIGEST → 写 digest-N.md → 含"建议结束"？→ 早停
3. BLOCKED 检测（digest + jsonl 兜底 + 日志尾三处）→ 求助？→ 停止调度，待人工
4. 投降检测（"打不动了/测不了"类措辞）→ 下一段注入强制换角度指令（最多 2 次）
5. 都没有 → 重新 infer_phase（产物变了阶段就推进）→ 下一段
```

这就是停止信号三通道：Agent 自己喊求助（BLOCKED）、自己认为干完了（建议结束）、harness 掐表（预算尽）。实战里 Agent 曾在首段就正确喊出 BLOCKED 省掉 2/3 预算——但一次编码故障让 harness 聋了，才有了 jsonl 兜底通道的诞生。

### 第 7 步：段与段之间——切片与记忆

为什么切段：LLM 的能力随上下文膨胀而衰减，九十分钟连续会话的后半段，它又笨又贵。所以每段都是全新会话——**上一段的"它"和这一段的"它"是两个不同的侦探**。

代价是新侦探不记得上一任干了什么。补偿是双通道记忆：

- **digest（叙事通道）**：上一任写的交接散文，注入下一段 prompt 尾部（末 2500 字符）
- **事件流（事实通道）**：runlog 事件（几点发现什么）+ 证据文件清单，注入下一段开头
- **jsonl 兜底（容灾通道）**：叙事丢了（编码/管道故障）就从 pi 自己落盘的会话文件恢复

已知残留风险：digest 是自由散文，可能幻觉、可能缺失。兜底方案解决"丢失"，没解决"幻觉"——结构化事实账本（facts ledger）在演进路线里。

### 第 8 步：值池联动引擎（最"人类智慧"的部分）

recon 门要求的契约文件里，每个端点的方法/参数/认证方式全部从 JS 提取；值池则是 JS 里扒出来的泄露值（token、id、手机号…）。PairingEngine 把两者叉乘：

> A 接口的响应值，自动注入 B 接口的输入——把人类工程师"诶这个 id 拿去别的接口试试"的联想，编码成了规则。

配对还带优先级和门控：HIGH/CRITICAL 配对没测完，BRIEF 会警告"先测完它们再开新面"。扰动字典（状态翻转到 -1、pageSize=10000 这类动作原子）正在逐步接入语义组。

### 第 9 步：报告与 triage 硬门

全部段结束（或早停/待人工）→ 汇总 summary + evidence → 生成 `runtime/outputs/report-*.md`。生成前过 triage 硬门：每条 CONFIRMED 做四项机械检查（有类型 / 有 URL / 有证据文件 / 有影响描述），不过就自动降 PENDING 并标注原因。为什么：**SRC 提交信誉是资产，误报比漏报更伤**——宁缺勿滥是编码进系统的价值观。

### 第 10 步：webui 看板

卡片状态机（运行中/中断/待人工/已完成…）、实时日志（会话镜像）、调度器日志、事件流、证据浏览、历史报告。日常操作只在这一层；`diag.sh` 是这一层的体检仪。

## 三、知识飞轮

飞轮的本质：**把一次实战的经验，变成所有未来目标的能力**。载体是 Markdown，机制是文件系统。

| 层 | 内容 | 什么时候被读 |
|---|---|---|
| `agents/` 角色卡 ×7 | "这个阶段你是谁、交付什么标准" | 对应相位，定调视角 |
| `skills/` 手册 ×22 | 一类操作的完整步骤（登录审计、业务遍历、AI 应用攻击、JS 分析…） | 特征命中 |
| `references/` 速查 ×27 | 不需要步骤、只需要查的东西（WAF 签名表、决策树、扰动字典、CVE 链、合规 TIER） | 参数/指纹命中 |

为什么是文件而不是数据库/RAG：Agent 的读取方式就是 `cat`，零基础设施；git 可版本化，改一行全局生效；每段只按需读 2-3 个（读取索引控制），不会像 RAG 一样塞一堆弱相关文本污染上下文。

飞轮的两种消化粒度：

- **案例级**（实战台账）：某类系统怎么打的 → 同栈目标指纹命中后整段平移打法
- **动作级**（业务遍历方法论 + 扰动字典）：对任何参数可做的扰动原子——不依赖具体案例，任何目标都适用

闭环：实战 → 报告/日志 → 消化进 knowledge → 方法论读取表登记触发条件 → 下个目标自动生效。这是经验积累的正规化，Agent 复刻了人类渗透工程师的成长方式。

## 四、合规与安全：为什么在 harness 层

| 防线 | 位置 | 防什么 |
|---|---|---|
| 白名单 | `targets.txt` + BRIEF 首节 | 越界测试 |
| 相位门控 | `infer_phase` | 未侦察先开火 |
| TIER 操作分级 | 合规速查（recon 必读） | ≤5 条越权证明、禁爆破禁 DoS |
| 登录限速 | BRIEF 账号段硬文案 | 打挂认证接口 |
| 停止信号 | 调度器 | 空烧预算 |
| triage | 报告层 | 误报出厂 |

原则：**能写成代码检查的，绝不写成 prompt 恳求**。SAFE MODE（WAF 后限速降档）就是典型——它不是建议，是 Agent 读了指纹后必须遵守的操作模式。

## 五、双平台与工程教训

本机 Windows 管调试，VPS Ubuntu 管夜跑——同一套代码。首次在 Linux 服务器上运行时暴露了五个"平台假设"类 bug，每个都是一条教训：

| 坑 | 教训 |
|---|---|
| pydantic 在 py3.8 炸 `list[X]` 注解 | pydantic 模型注解用 `typing.` 前缀 |
| GBK 管道吞掉整段收工输出 | 管道显式 `encoding="utf-8"` + 关键信号要有第二通道 |
| 依赖装了 latest、CLI 参数变了 | 依赖钉版本 |
| 运行时要求更高的 Node 引擎 | 引擎要求要核对，服务级隔离解决 |
| 进程存活探测用了平台专有命令 | 跨平台函数永远做 `os.name` 分支 |

这些教训催生了演进路线里的一条观察项：同类平台问题再出现，就上 Ubuntu CI。

## 六、设计自检

读完上面，应该能不假思索地回答：

1. 为什么模型说"我做完了"不算数？——进度=落盘产物，状态机不信嘴。
2. 段之间模型失忆了怎么办？——digest 叙事 + 事件流事实 + jsonl 兜底，三通道。
3. 新增一个渗透手法，要动几处代码？——零代码：knowledge 加文件 + 读取表登记一行。
4. BLOCKED 和"建议结束"都会停任务，区别在哪？——前者待人工等线索续跑，后者归档出报告。
5. 为什么给 Agent 的工具是 CLI 脚本而不是 MCP？——Agent 的手是 bash，CLI 跨平台零适配、输出天然可落盘。
6. Cookie 为什么存任务目录不进 `targets.txt`？——targets.txt 入 git，Cookie 是活凭据。

## 快速开始

依赖 Python 3.10+、Node.js 22+ 与 [pi-coding-agent](https://github.com/badlogic/pi-mono)（建议钉版本 `@0.84.1`），以及任一 OpenAI 兼容的大模型 API Key。

```bash
pip install -r requirements.txt
copy .env.example .env                    # 填写模型 API Key
copy targets.example.txt targets.txt      # 每行一个授权目标
python bigdan.py --dry-run && python bigdan.py
```

控制台方式（推荐）：

```bash
python -X utf8 -m webui.server            # http://127.0.0.1:8865
```

支持整批粘贴目标、按站点隔离的多账号 Cookie 注入、任务中途补给线索。VPS 夜跑形态见 [docs/DEPLOY.md](docs/DEPLOY.md)。

## 安全边界

仅测试 `targets.txt` 白名单内的授权目标；越权验证以不超过五条数据为证明尺度；禁止 DoS、批量爆破与破坏性操作，登录尝试限速且命中即停；密钥、凭据与在测目标不入库。使用者须自行确保对目标拥有合法授权，因使用本项目产生的后果由使用者承担。
